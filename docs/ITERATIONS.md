# v0.2.0 迭代记录（2026-09-16）

基线：v0.1.0，提交 cd7dfa6e3c3b1a9cb8717c2ece066b4ad8a1d044。每轮记录实际问题、修改与验证；本文件中的完成状态随验证更新。测试通过不等于全输入无缺陷或赛事获奖保证。

## 第 1 轮：日志处理的真实数据保真与管道行为

- 发现：JSON.parse 后重新 stringify 会将订单号 9007199254740993 改为 9007199254740992，也会改变负零与超大指数。旧版“保留输入”描述因此不成立。
- 修复：验证输入对象和 ip 后，将原 JSON 对象直接嵌入结果，保留数字与转义写法。下游自己的 JSON 解析器仍须正确处理大整数。
- 发现：输出未等待写入完成，慢消费者可能积压输出；关闭管道未统一诊断。
- 修复：每行等待写入回调；输出失败以 host-output-error 写入 stderr，退出码 2；不误报为坏 JSON 行。
- 验证：8 组 CLI 测试通过，包括精确数字、1,000 条慢消费完整输出和关闭管道错误。

## 第 2 轮：公开字段提取与日志接入

- 新增 Value.at_pointer、Reader.project 和 Projection，支持国家代码、坐标、ASN、数组元素与自定义字段。
- 路径采用 [RFC 6901](https://www.rfc-editor.org/rfc/rfc6901) 字符串形式；支持空根路径、空键、Unicode、~0/~1 转义；非规范数组下标作为未解析字段处理，错误转义单独报错。
- 新增 project 命令及 enrich --field；字段缺失为 missing，IP 未命中为 not_found，解析失败为 error。
- 每条记录完整解码一次，再选择字段；最多 64 个路径，路径最长 2,048 个 UTF-16 码元 / 128 段。重复路径拒绝；重叠选择的值数与载荷合计另受相同资源上限约束。
- 独立 MoonBit 消费模块已改用公开 project 接口完成 ASN 汇总。
- 验证：JS / Wasm GC 各 15 组核心测试通过，10 组 CLI 测试通过，独立消费模块两个后端各 1 组测试通过。

## 第 3 轮：原始浮点位与格式边界

- 新测试实际复现 signaling NaN 位被转换改变的问题；失败输出保留在 verification/regressions/nan-before-fix.log。
- Real32 / Real64 改为携带 Float32Value / Float64Value，以 bits 为事实来源；number() 仅用于数值运算与展示，JSON 的 bits 不再从转换后的数值反推。这是 v0.2.0 的公开类型变更，普通 CLI JSON 结构保持兼容。
- 增加正负零、无穷、不同 NaN 位模式、字符串长度编码 28/29/284/285/65820/65821、资源预算等值和差一边界回归。
- 从同一固定官方归档补充 21 个边界文件：深层嵌套、越界、分隔区指针、超大容器、UINT64_MAX 时间戳和资源边界；查询与字段提取都检查。
- 验证：JS / Wasm GC 各 18 组核心测试通过，21 个新增官方边界场景全部通过。部分坏文件在元数据/布局阶段提前拒绝，并不等于到达文件名指代的后续错误。
- 原有 value-limit 边界和 pointer-heavy 样例按本库“指针也计工作量”策略拒绝；不声称所有合法且复杂的记录都在默认资源配置内。打开仍只验证布局、元数据，查询只验证访问路径，不是整库认证。
